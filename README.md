# رادار التقنية: خط معالجة الوكيل (v0.7 — بعد اختبار الأسبوع السادس)

> تقرير الاختبار الكامل: [TEST_REPORT_WEEK6.md](TEST_REPORT_WEEK6.md) — والتقرير الأسبوعي للفورم: [WEEKLY_REPORT_WEEK6.md](WEEKLY_REPORT_WEEK6.md)

## الملفات
- `radar_pipeline.py`: السكربت الكامل (جلب، تنظيف، تكرار، تصنيف، تلخيص، تحقق، حفظ، تصدير). لا يحتاج `pip install`.
- `test_pipeline.py`: اختبارات تعمل بدون إنترنت ببيانات تجريبية.
- `radar_workflow.n8n.json`: ملف n8n (جدولة كل ساعة، تشغيل السكربت، تنبيه تيليجرام للثغرات الحرجة).

## المتطلبات
1. Python 3.9 أو أحدث.
2. Ollama مع نموذج (الافتراضي `qwen3:8b`): `ollama pull qwen3:8b` — اختير بعد مقارنة الأسبوع السادس (qwen2.5:7b كان يخلط الصينية في الملخصات)
3. اختياري: مفتاح NVD المجاني، وبوت تيليجرام (التوكن ورقم المحادثة).

## تجربة سريعة
```
python test_pipeline.py                      # اختبارات بدون إنترنت
python radar_pipeline.py --no-llm --no-alert # أول جلب حقيقي بدون نموذج وبدون تنبيه
python radar_pipeline.py                     # التشغيل الكامل
```
الناتج: قاعدة `radar.db` وملف `site/data.json` (يُقرأ منه الموقع).

## الموقع
- `site/index.html` صفحة واحدة تقرأ `site/data.json`: تنبيه بالثغرات الحرجة، وبحث، وتصفية حسب النوع والخطورة، وتعمل على الجوال وبالوضع الليلي.
- تجربة محلية: `python -m http.server 8765 --directory site` ثم افتح `http://127.0.0.1:8765` (فتح الملف مباشرة لا يحمّل البيانات).
- النشر: `.github/workflows/pages.yml` ينشر مجلد `site` على GitHub Pages مع كل رفع إلى `main`. في إعدادات المستودع: Settings → Pages → Source: **GitHub Actions**.
- التحديث التلقائي: `update_site.bat` يشغّل الوكيل ثم يرفع `data.json` الجديد. اجعله يعمل كل ساعة من Task Scheduler.

## متغيرات البيئة (اختيارية)
`OLLAMA_MODEL` اسم النموذج، `OLLAMA_URL`، `NVD_API_KEY`، `TELEGRAM_TOKEN`، `TELEGRAM_CHAT_ID`، `RADAR_FEEDS` (روابط RSS مفصولة بفاصلة).

## ربطه مع n8n
1. في n8n 2.0 وما بعده عقدة Execute Command معطلة افتراضيًا ومتاحة للاستضافة الذاتية فقط. لتفعيلها اضبط قبل التشغيل: `N8N_ENABLE_EXECUTE_COMMAND=true` و `NODES_EXCLUDE=[]`.
2. استورد `radar_workflow.n8n.json` من قائمة Import.
3. عدّل مسار السكربت في عقدة Run radar pipeline، وأضف اعتماد تيليجرام و `chatId` في عقدة Telegram alert.
4. شغّل الـ workflow يدويًا مرة للتجربة ثم فعّله.

إذا تعذر تفعيل Execute Command: شغّل السكربت بدون `--no-alert` عبر Task Scheduler (ويندوز) أو cron، وسيرسل التنبيه بنفسه عند ضبط متغيرات تيليجرام.

## ما تغيّر في الأسبوع السادس
- درجة CVSS لعناصر CISA KEV تُجلب من NVD، ويُفضَّل تقييم NVD الرسمي (Primary).
- استبعاد CVE المرفوض، وخطورة «unknown» للثغرة غير المقيّمة.
- استخراج النظام المتأثر من وصف الثغرة.
- خلاصات RSS تقنية فقط.
- تلخيص المهم فقط (الأخبار + الثغرات العالية والحرجة)، وملخص قالبي للباقي، وحد `--max-llm` (30 افتراضياً).
- حارس جودة للملخص: يمنع الحروف الأجنبية والكلمات المشوهة والأرقام والكلمات غير الموجودة في المصدر.
- منع إغراق التنبيهات: 5 رسائل للأهم + رسالة ملخّصة. الناتج فيه `alert_messages` جاهزة لـ n8n.
- إعادة الاختبار: `python quality/week6_eval.py --round N` ثم `python quality/score.py`.

## قيود معروفة (من اختبار الأسبوع السادس)
- بعض الملخصات يمنعها حارس الجودة، فتظهر بالعنوان والرابط فقط. وأخطاء المعنى بالكلمات (مثل «مئات» بدل «عشرات») لا تُكشف آلياً.
- صفحة الموقع يجب أن تعرض قيمة الخطورة الجديدة `unknown` (غير مقيّمة بعد).
- لا تضع قاعدة `radar.db` داخل مجلد مشترك أو متزامن (OneDrive، مجلد مشترك مع بيئة افتراضية): ظهر خطأ `disk I/O error`. ضعها في مجلد محلي عادي.
- عنوان NVD الفعلي هو `services.nvd.nist.gov`، فإذا كانت هناك قائمة نطاقات مسموحة يجب إضافته بهذا الاسم.
- التصنيف بالكلمات المفتاحية يخطئ عند ذكر جهاز بشكل عابر (مثال: خبر تعطل TikTok يذكر iPhone).

## ما لم يُختبر بعد
اختُبر في الأسبوع السادس: الجلب الحقيقي من NVD وCISA وRSS، وجودة التلخيص العربي (3 جولات × 20 عنصراً).
باقٍ: إرسال تيليجرام الفعلي (يحتاج توكن)، واستيراد ملف n8n في n8n نفسه. أي خطأ يظهر يُسجل في جدول `errors`.
